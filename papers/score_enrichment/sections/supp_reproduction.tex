\section{Reproducibility specification}\label{sup:reproduction}
The central experiment is identified by protocol \texttt{KAHM-SCORE-20261102-v1}. Its configuration, 256-task roster, primary family, and scientific-source manifest are supplied with the code. The preproduction source and the completed result release have separate identities. Source files, analysis records, and stage receipts are preserved without changing their historical contents.

\subsection{Four distinct reproduction tasks}
A document build uses the supplied LaTeX sources, bibliography, and static tables. The table builder regenerates displays from compact released CSV records. Neither operation refits a forecasting model. A saved-loss checker independently recomputes all 2,560 paired differences, 40 intervals and decisions, and 416 C/D procedure-summary rows, conditional on the supplied losses.

Selected-model replay additionally requires prepared episodes and portable JSON/NPZ states. The full computational audit requires all candidate fits and retained predictions. The release inventory describes sixteen numerical archives totaling 9.024 GiB. The complete archives are not included in the compact materials, and a public download location has not been established. The compact records therefore support verification of saved-loss statistics but do not, by themselves, support replay of the released fitted models. The inventory identifies required bytes and membership; it does not establish their availability. Source sufficient to regenerate the cohort is supplied separately in the attributed research package, subject to the recorded environment requirements below.

Full regeneration uses the immutable scientific source in a new output tree. The command sequence is initialization, A/B preparation, fitting, complete fit sealing, C/D preparation, prediction, complete prediction sealing, scoring, analysis, audit, and release. Existing completed evidence is not an output workspace. Re-executing the same cohort is computational reproduction rather than additional independent statistical evidence. Timestamps and outer archive bytes can differ; substantive numerical arrays use the declared tolerances.

\subsection{Environment and portability}
The recorded environment uses Python 3.13.5, NumPy 2.3.5, SciPy 1.17.0, scikit-learn 1.8.0, threadpoolctl 3.6.0, and pytest 9.0.2. Production uses three fresh-process workers and one numerical thread per worker. The environment record also identifies the Linux platform, numerical libraries, and architecture. The preflight rejects a changed environment signature; source availability alone does not guarantee bitwise reproduction on another platform. A port requires explicit validation and a separately recorded environment or source amendment, not bypassing the check while claiming exact fidelity.

\subsection{Evidence provenance}
The final release receipt binds the passing audit and released analysis. The source freeze records the prospective method; the earlier analysis receipt predates the completed audit. These records describe different points in the execution and are interpreted using their own scope. Hash checks establish byte identity, not independent scientific validity. The full numerical audit retains its shared-encoder limitation.

The accompanying repository documentation provides exact commands, archive restoration checks, source identities, and mappings from reported tables to input records. Related studies keep their own cohorts, confidence families, and availability statements.
